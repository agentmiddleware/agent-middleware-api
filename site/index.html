01 / The quickstart

Make your first call

This runs one call through the gateway with a fresh permit and a request key. It needs Python 3.10 or newer.

git clone https://github.com/agentmiddleware/amw-demo.git
cd amw-demo
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
export AMW_API_KEY='YOUR_DEMO_KEY'
export AMW_WALLET_ID='YOUR_WALLET_ID'
python examples/permit_echo_retry.py

Get a demo key to fill in the two export lines.

Expected output

1. Creating a permit scoped to partner.echo ...
   Permit permit-... issued.
2. Calling partner.echo through the gateway ...
   Receipt id: rcpt-...

Your permit was created. The call ran once. The receipt id is your proof of the gateway result.

Retry with the same key

3. Retrying with the SAME key and SAME arguments ...
   Receipt id: rcpt-...

Same receipt. The tool did not run again.

Check the receipt offline

4. Fetching the portable receipt and verifying it offline ...
   Verified receipt rcpt-... offline.

The script fetches the receipt and public keys, then checks the signature on your machine. See a published sample and verifier.

0 verified · 1 signature does not match · 2 cannot tell

Receipts sign hashes of the request and response, not their content. They do not prove the tool was right.

02 / How it works

Three things to know

Permit

A signed note that says what your agent may do: which tool, how many credits, and until when.

Request key

A name you pick for one action. Send the same key again and you get the first result back instead of a new action. It is sent as Idempotency-Key, or idempotency_key in the call body.

Receipt

Signed proof of what happened on a call. Anyone can check it offline with our public key.

04 / When not to use it

Know where the boundary ends.

The gateway receipt records what happened at the gateway. Your tool remains the source of truth for its own effect. Read the limits.
