00 / Operational problem

Authorization alone does not make retries safe.

A valid call can still commit its effect and lose the response. Blind retry may duplicate the action; a log cannot decide whether the downstream effect occurred.

The middleware preserves one gateway transaction identity and an honest uncertainty state without replacing your agent framework or downstream source of truth.

  1. Before Bind the action

    Tool, wallet, configured allowance, immutable payload, accepted key, and scope.

  2. During Claim dispatch once

    One accepted logical-action identity cannot become a second configured-upstream dispatch or debit.

  3. After Preserve uncertainty

    delivery_uncertain is linked to gateway evidence and requires external reconciliation.

01 / Governed path

One transaction state machine from authority to evidence.

Start with a consequential, autonomous, retry-sensitive mutation.

  1. 01Bind identity

    Bind the accepted idempotency key to one immutable invocation and authority context.

  2. 02Authorize

    Check the wallet-scoped caller, delegation, permit, tool scope, and expiry.

  3. 03Reserve

    Reserve the applicable configured permit, approval, credit, and call allowances.

  4. 04Debit

    Apply the configured debit once before the upstream dispatch claim.

  5. 05Claim dispatch

    Allow one worker to cross the configured-upstream boundary once.

  6. 06Classify

    Persist a confirmed outcome or delivery_uncertain; never automatically redispatch ambiguity.

  7. 07Receipt / audit

    Link the transaction state, authority consumption, debit, and gateway evidence.

  8. 08Reconcile

    Determine the actual effect from the authoritative external system.
