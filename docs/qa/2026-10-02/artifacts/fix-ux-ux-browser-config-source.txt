## Scope and method

The repository has a static marketing site (`site/`), a static operator index (`static/dashboard.html`), and an unshipped AWI TypeScript SDK (`awi_sdk/typescript/`). There is no React application or authenticated dashboard workflow. README.md:260–267 explicitly says there is no published TypeScript package; SDK findings therefore concern the checked-in integration surface, not an established public package release.

Risk order: (1) credentials/receipt claims and retry boundaries, (2) calculator correctness and public proof failure states, (3) SDK build and API ergonomics, (4) mobile/accessibility and asset performance. Runtime backend routes and Python suites belong to the backend pass; accessibility and screenshot fallback belong to the UX pass.

The test pyramid uses existing site checks first, browser-free component and transport-contract tests second, and browser smoke scenarios last. The component fallback executes the unmodified product JavaScript in jsdom; it does not establish layout, engine compatibility, focus behavior, or Web Vitals. No product behavior or package manifest was changed.

Timed exploratory charters:

| --- | --- | --- | --- |
| FE-C1: bootstrap and build | 10 minutes | Can a clean consumer build the static site and SDK without production settings? | Site builds with synthetic contact fixture; SDK declared build fails (FE-001). |
| FE-C2: public flow/browser smoke | 10 minutes | Do primary pages, calculator, proof, no-JS and mobile flows work across Chromium/Firefox/WebKit? | 24 cases collected; every engine failed at launch before navigation.
