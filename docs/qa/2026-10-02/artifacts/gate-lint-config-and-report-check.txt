## Exactly-once and new-key claim findings

The complete [claim inventory](CLAIMS-INVENTORY.md) records **343 occurrences across 133 tracked files**, with each occurrence assigned to a substantive family. [CLAIMS-REPORT.md](CLAIMS-REPORT.md) records exact source/implementation evidence, limitations and suggested treatment for BE-101 through BE-109. These are verification findings, not new defects:

- BE-101: accepted same-key gateway identity provides at-most-one dispatch/debit structure; PostgreSQL crash behavior needs its separate infrastructure proof.
- BE-102: arbitrary downstream exactly-once effect is not guaranteed without upstream support.
- BE-103: the default duplicate guard is `log`; a new key may dispatch and charge again.
- BE-104: opt-in `enforce` only covers matching permit/tool/arguments within the window, with permit opt-out respected.
- BE-105: standard `POST /mcp` creates another auto-permit for a new key, outside same-permit deduplication even when enforcement is enabled; this is already documented.
- BE-106: local dogfood proofs demonstrate their controlled replay scenario, not upstream crash semantics.
- BE-107: reservation/refund-once claims are partially verified by transactional structure and named tests.
- BE-108: approval/permit issuance-once claims are scoped to durable identity, not external notification delivery.
- BE-109: historical results, test assertions and unrelated one-time/QoS terminology are recorded without treating them as current end-to-end guarantees.

## Measurement rules

Backend coverage uses the same `app` source denominator before and after retained QA tests, with greenlet-aware tracing from `pyproject.toml`. Pass/fail counts and exclusions are reported separately from executed-line coverage. Coverage does not prove correctness, PostgreSQL parity, crash safety or production readiness.

The existing backend baseline and focused QA probes are running. Their final measured totals and artifacts are added when the backend pass closes. No percentage is inferred from prior runs.

## Frontend component scope

The browser-free fallback executes the real `site/pilot-fit.js` and `site/proof/proof.js` with jsdom and mocked local data, plus a transpiled TypeScript SDK with a fake transport. Node V8 coverage for the **two named web scripts only** is 100% lines, 90.38% branches and 100% functions. This is not whole-site or SDK coverage. Exact artifacts and final command results are listed in the frontend report at closeout.

The native Chromium, Firefox and WebKit baseline could not launch under the macOS sandbox. A blocked baseline is **not 0% coverage**. The separate Chrome computer-use fallback is exploratory evidence and is not substituted for the blocked cross-browser Playwright suite.

## Untested or incomplete areas

- Real remote MCP effects, databases, billing and provider integrations: prohibited.
- PostgreSQL-specific multiprocess locking/crash recovery: requires isolated local infrastructure, not supplied by SQLite tests.
- Hosted CI and deployed configuration/performance: orchestrator follow-up only.
- Full browser matrix and whole-site JS branch coverage: constrained by sandbox/tooling; final UX report records actual fallback evidence.
- Real screen-reader use and complete WCAG certification: beyond automated axe and DOM/keyboard checks.
