## Entry criteria

The qualification call may proceed when the founder verifies the private lead
and has authority to use the channel. No external test may proceed until all of
the following are recorded:

- The partner owns the agent, staging tool, consequential mutation, and
  authoritative effect record.
- A named partner engineer commits to operate the workflow on or before Sep 8.
- A duplicate or ambiguous result has a concrete business consequence; the
  current restriction and strongest existing solution are documented.
- The partner can persist an effect and then withhold the response, look up the
  effect independently, and reset the one-shot fault.
- The test uses synthetic or redacted data and a scoped, revocable credential.
- The actual staging ingress rejects an oversized request with HTTP 413 before
  application parsing. A proposed cap or app-level test is insufficient.
- Both arms use the same tool, native idempotency, fault placement, actions,
  measurements, and pre-agreed overhead limits. The baseline keeps every
  protection the partner would actually use.

The exact partner-owned acceptance sequence is in the [active sprint](../../30-day-customer-validation.md#pilot-acceptance-test), the operational placeholders and safety checks are in the [first-tool runbook](../../partner-first-tool-runbook.md), and the fair A/B method is in the [killer comparison](market.md#the-killer-comparison-experiment).

## Exit criteria

The action exits **continue narrow validation** only when all of these claims
have partner evidence:

1. The partner's tool commits one staging effect while its response is lost.
2. The gateway records signed, charged `delivery_uncertain`; exact replay
   produces no second gateway dispatch or debit.
3. The partner engineer uses the authoritative system to classify the effect
   and verifies the linked gateway receipt offline in the partner environment.
4. The A/B record shows whether the gateway changes business safety or total
   operating burden relative to the partner's strongest existing solution.
5. The buyer provides a paid pilot or a credible written commitment naming the
   buyer, budget path, owner, scope, and decision date.

Gateway evidence cannot establish downstream effect truth. Self-operated demos,
local fixtures, founder-issued receipts, and unsigned interest do not satisfy
these criteria.

## Stop criteria

- **Sep 3:** if the lead will not name a consequential mutation, current
  restriction, partner engineer, and experiment date, stop pilot preparation.
  Record the funnel failure; do not build features to manufacture fit.
- **Before exposure:** if authoritative effect lookup, fault/reset control,
  scoped staging data, or verified ingress 413 is absent, do not connect the
  gateway. Permit only configuration or documentation work needed for that
  exact partner blocker.
- **After A/B:** if the partner's existing controls already make ambiguous
  retry safe at acceptable cost, the inline dependency is unacceptable, or the
  partner sees no material incremental safety or burden reduction, stop core
  expansion. Retain the result as falsification evidence.
- **Sep 10 at 17:00 PDT:** if no paid pilot or written buyer/budget/date
  commitment exists, do not relabel technical success as commercial evidence.
- **Sep 11:** if the full exit criteria are unmet, pause new core capability.
  Reframe only when repeated named prospects document the same concrete blocker
  and the smallest existing-loop slice that would clear it.
